# LinkedIn Poster（LinkedIn自動投稿ツール）

Museに指示すると、MuseがLinkedInの**公式API**で自分のアカウントに投稿してくれる仕組みです。

ユーザーが自分でやるのは**事前準備だけ**です。準備が終われば、投稿はターミナルコマンドではなく、Museとの会話で行います。

> 「この内容でLinkedInに投稿して」→ Museが投稿 → 投稿のURLを返却

このリポジトリのTypeScriptプログラムは、その準備の一つである**アクセストークンの発行**を担当します。

---

## 0. 全体の流れ

| 段階 | やること | 担当 | 回数 |
|---|---|---|---|
| 1 | LinkedIn開発者アプリを作る | ユーザー | 最初に1回 |
| 2 | アクセストークンを発行する（`npm run login`） | ユーザー | 最初に1回＋60日ごと |
| 3 | アクセストークンをMuseのSecure Vaultに登録する | ユーザー | 発行するたび |
| 4 | 投稿する（Museに指示） | Muse | 投稿するたび |

1〜3が事前準備です。4からはコマンドを打つ必要はありません。

---

## 1. 事前準備（ユーザー）

- **LinkedInアカウント**: 投稿する本人のアカウント
- **LinkedInの会社ページ1つ**: アプリを作るときに「このアプリがどの会社に属するか」を聞かれるため必要です。
  - 会社がなくても大丈夫です。個人用の空のページを新しく作って紐づければOKです。
- **Node.js**: アクセストークン発行プログラムの実行に必要です。なければ https://nodejs.org からインストールしてください。

---

## 2. LinkedIn開発者アプリを作る（ユーザー、最初に1回）

LinkedInは「誰がAPIを使うのか」を知る必要があるため、まず**アプリ**（プログラムの身分証）を登録します。

### 2-1. アプリを作成
1. https://developer.linkedin.com/ にアクセスしてログイン
2. **My apps → Create app** をクリック
3. 入力項目
   - **App name**: 任意の名前（例: `my-linkedin-poster`）
   - **LinkedIn Page**: 上で用意した会社ページを選択
   - **App logo**: 任意の画像（必須項目）
4. 規約に同意して **Create app**

### 2-2. 必要な機能（Products）を追加
アプリ画面の **Products** タブで、下の2つを **Request access** で追加します。どちらも別途審査なしですぐに有効になります。

| 追加するProduct | 役割 | 得られる権限（scope） |
|---|---|---|
| **Share on LinkedIn** | 自分のアカウント名義で投稿する | `w_member_social` |
| **Sign In with LinkedIn using OpenID Connect** | 「自分が誰か」を確認する（ログイン認証の方式の一つ） | `openid`, `profile` |

### 2-3. リダイレクトURLを登録
1. **Auth** タブ → **OAuth 2.0 settings** → **Redirect URLs** の横の鉛筆アイコンをクリック
2. 下のURLを追加して保存

```
http://localhost:3000/callback
```

> リダイレクトURLとは、ログインを終えた後にLinkedInがユーザーを戻す先のURLです。`localhost`は「自分のコンピュータ自身」を意味します。
> `.env`の`REDIRECT_URI`とここで登録したURLが違うと、ログインが失敗します。

### 2-4. 鍵を2つ控えておく
**Auth** タブの上部で下の2つの値を確認します。

- **Client ID**: アプリのID
- **Client Secret**: アプリのパスワード（**他人に見せたり、GitHubに上げたりしないでください**）

---

## 3. アクセストークンを発行する（ユーザー、最初に1回＋60日ごと）

自分で投稿する段階ではなく、**Museに渡すアクセストークンを作る段階**です。

### 3-1. 自分のコンピュータの準備（最初に1回）

```bash
# 1) プロジェクトフォルダへ移動
cd linkedin-poster

# 2) 必要な部品（パッケージ）をインストール
npm install

# 3) 設定ファイルを作る
cp .env.example .env        # Windows（コマンドプロンプト）は: copy .env.example .env
```

`.env` ファイルを開いて値を入れます。

```env
LINKEDIN_CLIENT_ID=2-4でコピーしたClient ID
LINKEDIN_CLIENT_SECRET=2-4でコピーしたClient Secret
REDIRECT_URI=http://localhost:3000/callback
LINKEDIN_VERSION=202608
```

- `LINKEDIN_VERSION`はLinkedIn APIのバージョン（`年+月`の6桁）です。古いバージョンはLinkedInが定期的に止めるため、バージョン関連のエラーが出たら、より新しい月（例: `202610`）に変えてみてください。

### 3-2. ログインしてアクセストークンを受け取る

```bash
npm run login
```

1. ターミナルに長いURLが出ます。それをコピーしてブラウザに貼ってください。
2. LinkedInにログインして **許可（Allow）** を押します。
3. 「ログイン完了！」の画面が出れば成功です。ターミナルに戻ってください。
4. プロジェクトフォルダに`.token.json`ファイルができます。これが **アクセストークン** です。

> アクセストークンは約 **60日** 有効で、自動更新（リフレッシュ）はありません。期限が切れたら、この段階をもう一度実行してください。

---

## 4. Museにアクセストークンを登録する（ユーザー、発行するたび）

1. MuseにLinkedIn接続（またはトークン更新）を頼むと、セキュリティ入力カードが出ます。
2. `.token.json`ファイルの`accessToken`の値をそのカードに入れます。**チャット欄に直接送らないでください。**
3. アクセストークンの原文はMuseのSecure Vault（セキュリティ保管庫）に保存されます。ワークスペースのファイルやコードには入りません。

登録が終われば、事前準備は完了です。

---

## 5. 投稿する（Museに指示）

ターミナルにコマンドは打ちません。Museに会話で指示します。

```
この内容でLinkedInに投稿して:
（投稿したい文章）
```

- 外部の記事を繋げたい場合は、URLを一緒に渡せばリンクカードとして付きます。（「このURLをリンクカードで付けて投稿して: https://…」）
- Museは投稿前に **正確な文章を先に見せて、承認を受けた後にだけ** 投稿します。
- 投稿が終わると、Museが投稿のURLを教えてくれます。

検証状態（2026-11-03）: MuseがSecure Vaultのアクセストークンでプロフィール取得（`GET /v2/userinfo`）を呼び出し、**HTTP 200** の成功を確認しました。投稿の呼び出しもこの接続で構成されていますが、実際の投稿成功はまだ未検証です。

---

## 6. セキュリティ上の注意

- `.env`（Client Secretを含む）と`.token.json`（アクセストークン）は **パスワードと同じ** です。
  - GitHub、メッセンジャー、スクリーンショットなどで共有しないでください。
  - すでに`.gitignore`（Gitに上げないファイル一覧）に入っています。
- 漏洩が疑われる場合は、開発者サイトの **Auth** タブでClient Secretを再発行してください。
- このプログラムは **個人アカウント専用** です。LinkedInの利用規約とAPI規約を守って使ってください。（スパム的な大量投稿はアカウント制限の原因になります。）

---

## 7. できないこと（このプロジェクトの範囲外）

- **LinkedInネイティブ記事（長文）を書くこと**: LinkedInの中で直接書く長文は公式APIがないため、プログラムでは投稿できません。LinkedInのウェブサイトで直接書く必要があります。（外部記事のURLを繋ぐリンク共有投稿は可能です。）
- **画像・リンクを文章の途中に挿入すること**: 添付物（画像、リンクカード）は常に文章の下の固定位置にだけ付き、途中に差し込むことはできません。これはこのプログラムの限界ではなく、LinkedInの投稿自体の仕様なので、LinkedInアプリで直接上げても同じです。

## 8. フォルダ構成

```
linkedin-poster/
├─ src/
│  ├─ config.ts   設定値を読む（.env）
│  ├─ login.ts    ログイン → アクセストークンを発行・保存
│  └─ post.ts     アクセストークンで投稿
├─ .env.example   設定ファイルの見本
├─ .gitignore     Gitに上げないファイル一覧
├─ package.json   パッケージ/コマンド一覧
└─ tsconfig.json  TypeScript設定
```
